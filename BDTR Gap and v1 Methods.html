1. Where the gap comes from

We reran BDTR with the same algorithm logic in a Python port (300 seeds). Changing one setting at a time shows how much each added setting costs.

Paper, BDTR
82.9%

Source: Python port, 300 seeds, same BDTR logic. Not re-run in MATLAB.

What this means

  • Deadlines and travel are the two biggest drivers. We added both. The paper's experiments disregard flight time and communication delay, and it reports no deadline values.
  • Attack severity and timing explain the rest. With deadlines and travel removed, completion is 99.8%, 97.6% and 93.2% at 2, 3 and 4 attacks. The paper's exact attack count and timing are not given. We only have strengths of 20, 30 and 40% and first-attack time of 15 s.
  • Failures in BDTR are deadline expiries. In the port, capability-blocked unfinished tasks are 0.00%; horizon-limited unfinished tasks are 0.33%.
  • The paper is ambiguous in places we had to fill in. Algorithm 1 has two typos (Ucand and Kswap are written as empty sets). The optimal task k* is undefined. The Phase 1 sort key is undefined. The paper has no coordinates.

4. SABR: how it decides, each timestep

SABR is a centralized, deadline-aware reallocator. Phase 1 solves one assignment problem over the tasks needing a new UAV. Phase 2 reorders and repairs the queues. The pseudocode below is the decision logic of v1, step by step.

Per timestep t (dt = 1 s)

1.  for each task k with release time = t:
        status[k] = unassigned

2.  apply capability changes scheduled at t

3.  if any UAV u lost a capability at t:
        for each task k queued on u that u can no longer do:
            status[k] = atrisk
        repeat:
            REALLOCATE(pool = atrisk tasks)
        until no new task is assigned
        PHASE2(all queues)

4.  deadline sweep:
        for each task k not complete, not failed, not pending:
            if t >= deadline[k]:
                status[k] = failed
                remove k from its queue

5.  move every UAV one step toward its queue head (speed 5 m/s)
        execute the queue head when the UAV is on station

6.  for each idle UAV:
        REALLOCATE(pool = unassigned tasks)

REALLOCATE(pool)

A. build an N x N cost matrix, every cell = DUMMY (1e6)

B. for each task k in pool, each UAV u:
       if u can perform k's payload:
           dist   = distance(u, k) / speed
           c_dist = dist / (refDistance / refSpeed)
           c_load = (queueLen(u) * execTime[k]) / (refQueueLen * refExecTime)
           c_comp = (estFinish(u, k, t) - t) / deadline[k]
           cost   = 0.5 * c_dist + 0.3 * c_load + 0.2 * c_comp
           if k is already assigned to u:
               cost = cost - 0.4        # keeps the current UAV; name says "penalty" but it is a bonus
           matrix[k][u] = cost

C. assignment = exact one-to-one solve of the matrix   # LAP, O(n^3)

D. for each (k, u) in assignment:
       if matrix[k][u] < DUMMY - 1:  commit k to u
       else:                          status[k] = atrisk

E. preemption, unassigned tasks only, in priority order (high first, then index):
       for each task k:
           candidates = []
           for each UAV u not already committed in this pass, feasible for k:
               j = u's queued task that has not started
               if priority[k] > priority[j]
                  and j has a safe alternative UAV
                  and estFinish(u, k, t) with empty queue <= deadline[k]:
                   candidates += (u, j, cost(k, u))
           if candidates not empty:
               take the lowest-cost candidate
               commit k to u; status[j] = atrisk

PHASE2(queues)

1.  for each UAV u:
        freeze the head task if it is in progress
        sort the free suffix by (deadline, index)
        keep the new order only if (late count, total tardiness) improves

2.  REPAIR (repeat until no move):
        find the single transfer (task from a donor queue into a recipient queue)
        that increases the on-time count
        recipient length after move must be <= max(nomCap, donorLen - 1)
        if none: stop
        apply it; lock the moved task

3.  DESCENT (only while the longest queue > nomCap):
        for donors from longest queue down, recipients with length <= M - 2:
            move an unlocked task that stays on time
        each task moves at most once

5. CARA: how it decides, each timestep

CARA is an event-driven reallocator. It replans only when something changes: a release, a capability loss, or a heartbeat when a free task is about to become late. Any work a UAV can no longer delay is frozen, because a new command takes 1.05 s to reach the aircraft.

Constants

tauLink = 0.5 s          one-way link delay
tauCpu  = 0.05 s        planner compute time
Tc      = 2*tauLink + tauCpu = 1.05 s   command window
chi     = 30 s           penalty for moving a task to another UAV
Th      = 5 s            heartbeat period
lateCap = nU             at most nU late free tasks are replanned per event

Per timestep t (dt = 1 s)

1.  for each task k with release time = t:
        status[k] = unassigned; flag = released

2.  apply capability changes scheduled at t; if any, flag = degraded

3.  heartbeat = (t >= nextBeat) AND some free task would be late by t + Tc
    if heartbeat: flag = heartbeat

4.  if flag set:
        CARA(t)
        nextBeat = t + Th

5.  deadline sweep (same rule as SABR)

6.  move each UAV, but only when t >= commandReadyTime[u]

CARA(t)

lockTime = t + Tc
frozen prefix of each UAV = tasks in progress, or starting at or before lockTime

A. frozen tasks the UAV can no longer do:
       status[k] = failed (reason: FrozenLost); not reassigned

B. free tasks the UAV can no longer do:
       status[k] = atrisk; add to must-place set

C. must = illegal tasks  union  unassigned tasks
   latePool = top lateCap free late tasks by tardiness, excluding must
   D = must  union  latePool
   capacity = |D| + nU

D. ASSIGNPOOL(must, mustPlace = true, capacity)
   ASSIGNPOOL(latePool, mustPlace = false, capacity - |must placed|)

E. any illegal task not re-placed:
       status[k] = failed (reason: Unsaved)

ASSIGNPOOL(pool, mustPlace, capacity):
    repeat until no change:
        for each task k in pool, UAV u:
            C[k][u] = BESTBID(k, u, mustPlace)  or UNMATCHED (5e5)
        pairs = exact one-to-one solve of C
        for each (k, u) in pairs, in task-index order:
            commit k to u at its best slot; lock k

BESTBID(k, u, mustPlace):
    for slot in { after frozen prefix, append to queue }:
        trial = insert k at slot
        if any task that was on time would become late: reject slot
        if k is on time in trial:
            cost = dFlight(u, k) + chi      (chi = 0 if u already holds k)
            keep slot
        else if mustPlace and no on-time slot found:
            cost = 1e5 + tardiness(k) + chi  # last resort, still placed late
        else:
            reject (non-must tasks need lateness to improve)
    return cheapest kept slot

6. Caveats for the presentation

MATLAB was not run in this session. The MATLAB numbers come from the saved summary CSV in the repo. The gap decomposition comes from the Python port, which uses the same algorithm logic. The MATLAB test file for the hand-built BDTR case exists but has not been executed.

  • Known leak in CARA: the 1.05 s communication window is not switched off by the paper-aligned profile. This affects CARA's comparison with the paper, not the BDTR result.
  • Known issue in SABR: the completion term divides by the deadline. With deadlines set to infinity it becomes 0, so the term silently disappears in paper-aligned runs.
  • Naming issue: the SABR "disruption penalty" is applied as a bonus of −0.4 for the current UAV. The code is correct for the intent (keep the task where it is), but the name is misleading.
  • Solver complexity: SABR Phase 1 is an exact assignment solve, which is O(n³). This matters for the complexity discussion later.
  • Not established: whether BDTR is close to an upper bound on completion under the paper's setting. That test has not been run.
